What's inside the box before subscribe

const obs = http.post('/api/watchlist', { movieId: 3 }) gives you a plain JavaScript object: four Observable objects nested like dolls. Each one knows what to do (operator) and which doll is inside it (source). The smallest doll holds your request. This is Angular 22's real code: of(req).pipe(concatMap(…), filter(…), map(…)).

doll1 obs = Observable operator: map(res => res.body)
What you got back. On the way out, it takes just the body out of the response.
doll2 .source = Observable operator: filter(e => e instanceof HttpResponse)
Lets only the final response through. Throws away "request sent" notices.
doll3 .source = Observable operator: concatMap(req => handler.handle(req))
The interceptor onion and the network live here. Nothing runs until someone subscribes.
doll4 .source = Observable created by: of(req)
Holds the request letter, ready to hand it out when asked.
HttpRequest { method: 'POST', url: '/api/watchlist', body: { movieId: 3 }, headers: HttpHeaders { (empty) }, responseType: 'json' }
network requestnot sent
interceptorsnot run
responsedoes not exist yet
your callbacknot called
before subscribe · t = 0 ms

Just a description

All four dolls exist, and that is all. Building them took microseconds and touched no network.

Build the dolls yourself

The code that makes each box

Every .pipe(operator) call wraps the Observable you already have in one new Observable. So you build the dolls from the inside out: first doll4, then wrap it, and so on. Hover a line to see its box, or press Next step above: the line that is working lights up too.

1import { of } from 'rxjs';
2import { concatMap, filter, map } from 'rxjs/operators';
3import { HttpRequest, HttpResponse } from '@angular/common/http';
4
5// the letter: a plain object, nothing is sent
6const req = new HttpRequest('POST', '/api/watchlist', { movieId: 3 });
7
8// build the dolls from the INSIDE out, one .pipe(operator) per doll
9const doll4 = of(req); // holds the letter
10const doll3 = doll4.pipe(concatMap(r => handler.handle(r))); // onion + network
11const doll2 = doll3.pipe(filter(e => e instanceof HttpResponse)); // only the response
12const doll1 = doll2.pipe(map(res => res.body)); // just the body
13
14// doll1 is exactly what http.post(...) returns to you
15doll1.source === doll2; // true
16doll2.source === doll3; // true
17doll3.source === doll4; // true
18
19// Angular writes the same four dolls in one line:
20const obs = of(req).pipe(
21 concatMap(r => handler.handle(r)), // → doll3
22 filter(e => e instanceof HttpResponse), // → doll2
23 map(res => res.body), // → doll1
24);

Same thing, two spellings. a.pipe(op1, op2, op3) is exactly a.pipe(op1).pipe(op2).pipe(op3). The operators are listed top to bottom, but each one wraps the result of the one above it, so the last operator (map) ends up as the outermost doll. handler is Angular's interceptor chain; you never build it yourself.

No Angular needed: save as dolls.mjs in any folder with RxJS (npm i rxjs), then run node dolls.mjs. A fake handler plays the server: it emits a "Sent" event straight away and the response 120 ms later, just like HttpClient.

4class FakeRequest { constructor(method, url, body) { Object.assign(this, { method, url, body }); } }
5class FakeResponse { constructor(body) { this.status = 201; this.body = body; } }
6let t0 = Date.now(); const t = () => `t=${String(Date.now() - t0).padStart(3)}ms`;

8// stands in for handler.handle(req): the interceptor onion + the network
9const handler = {
10 handle: req => new Observable(sub => {
11 console.log(t(), ' [network] request sent:', req.method, req.url);
12 sub.next({ type: 'Sent' }); // event 1: "request sent"
13 const id = setTimeout(() => {
14 sub.next(new FakeResponse({ id: 7, movieId: req.body.movieId })); // event 2: the response
15 sub.complete();
16 }, 120);
17 return () => clearTimeout(id); // what unsubscribe() cancels
18 }),
19};

31}));

Read the output top to bottom. Nothing in the operators runs until subscribe. subscribe() returns before the response arrives (line 6 of the output). The "Sent" event dies in filter, so your callback only ever sees the body.

What is inside an operator? Here is map written without RxJS's version. An operator is just a function that takes the doll inside (source) and returns a new, bigger doll.

1import { of, Observable } from 'rxjs';
2
3// map, written by hand: a NEW Observable that subscribes to the one inside it
4function myMap(fn) {
5 return source => new Observable(subscriber => {
6 console.log(' myMap: someone subscribed to me → I subscribe to my source');
7 return source.subscribe({
8 next: value => subscriber.next(fn(value)), // value comes OUT, transformed
9 error: err => subscriber.error(err),
10 complete: () => subscriber.complete(),
11 });
12 });
13}
14
15const inner = of({ status: 201, body: { id: 7 } });
16const outer = inner.pipe(myMap(res => res.body)); // same as myMap(res => res.body)(inner)
17
18console.log('built. nothing printed above this line yet.');
19outer.subscribe(v => console.log('callback got', v));
Real output
built. nothing printed above this line yet. myMap: someone subscribed to me → I subscribe to my source callback got { id: 7 }

Look at line 6: when someone subscribes to the outer doll, it subscribes to the doll inside it. That's why subscribing walks in (outside → in). Then values come back out through each next, and each doll changes the value on the way (line 8). Every RxJS operator works like this.

    Four rules that prevent most interceptor bugs

    Return next(req)

    Forget the return and the chain is broken: the request never leaves.

    Clone, don't mutate

    Requests are immutable. req.headers.set() returns a new object you then ignore, so it fails silently. Use req.clone({ setHeaders }).

    finalize for cleanup

    It runs after success, error and cancel. tap never sees a cancel.

    Catch, react, rethrow

    return throwError(() => err) after handling. Returning of(null) tells the component the request succeeded.
